# read-paper：本地论文 → 中文深读笔记

## 用途

用户给出一个论文标识后，本 skill 在当前工作目录（论文库根目录，可用 `--root <dir>` 覆盖）递归定位对应的本地 PDF，精读全文，产出一篇**全面、可溯源、可直接进入 Obsidian 知识库**的中文笔记，并更新 `paper-notes/index.md`。

## 必须遵守的边界

- 只处理用户已下载到本地的 PDF；输入只用于定位，不自动联网下载论文/代码。
- 找不到、命中多个候选时一律停下来让用户确认，绝不静默挑选或臆测。
- 笔记面向“遥感视觉方向的研二研究生”，中文为主；术语保留英文并在首现处给中文解释。
- 每个事实性判断都要有证据锚点；拿不到证据就写 `未披露/待验证`，禁止脑补数字或结论。
- 公式统一使用 Obsidian MathJax 语法（行内 `$...$`，块级 `$$...$$`），逐个给出通俗解释。
- “可写论文的选题”一节禁止把原论文已有创新点包装成新贡献。
- 联网只允许用于：核验论文作者声明的官方开源仓库、检索后续/相关论文；结果必须注明检索日期。

## 引用锚点格式

- 正文证据锚点统一写作 `【PDF p.<物理页码> | Sec.<x> | Eq./Fig./Tab.<y>】`，页码用 PDF 阅读器显示的物理页。
- 每篇笔记底部放标准引用、本地 PDF 路径、检索/生成日期、OCR 覆盖说明。

## 资源定位

脚本与模板与本 SKILL.md 同目录：
- `scripts/find_pdf.py`：按文件名模糊定位 PDF
- `scripts/extract_pdf.py`：按物理页抽取 PDF 文本（可 OCR）
- `scripts/merge_note.py`：写笔记并保留用户批注区
- `scripts/check_math.py`：静态校验 MathJax 公式
- `scripts/update_index.py`：重建 `paper-notes/index.md`
- `assets/paper-note-template.md`：笔记模板

若运行环境中不知道本 skill 的绝对路径，先用 `rg --files` 找到含 `read-paper/SKILL.md` 的目录。

## 通用执行命令

脚本一律通过 UV 运行；无网络或 uv 失败时退回系统 python3/python：

```text
uv run --no-project python "<skill>/scripts/<script>.py" <args>
```

## Step 1：定位 PDF

```text
uv run --no-project python "<skill>/scripts/find_pdf.py" "<用户给的名称>" --root <论文库根目录> --json
```

- 匹配时忽略大小写、空格、连字符、下划线等分隔符；容忍文件名前的“第一作者 + 年份/会议”前缀；支持题名连续关键词、文件名片段、arXiv ID、DOI。
- 只有一个强候选 → 使用它。
- 多个候选 → 打印候选列表（路径 + 匹配依据），请用户指定其中一个或给出更精确名称，然后继续。
- 零候选 → 报告“未找到”，并列出名称最相近的本地 PDF 供用户确认，不做任何猜测性精读。

## Step 2：抽取正文

先看 PDF 前 2 页定位元数据与结构，再按需抽取方法、实验、讨论、参考文献页：

```text
uv run --no-project python "<skill>/scripts/extract_pdf.py" "<pdf 路径>" --pages 1-3
uv run --no-project python "<skill>/scripts/extract_pdf.py" "<pdf 路径>" --pages 5-12
```

- 按 `--pages` 分小批读入，避免把整篇塞进上下文；记下每页的物理页码用于锚点。
- 若若干页文本为空（扫描版）：先用已有工具尝试 OCR（`--ocr`，需本机有 tesseract）；没有可用 OCR 时，明确告诉用户“以下页面无法读取：…”，按已读内容生成笔记并在“引用与溯源”标注覆盖率与不确定性，绝不假装读过缺失页面。

## Step 3：确定元数据与文件名

从首页/摘要区读取：标题、全部作者、年份、venue/arXiv/DOI、论文内声明的代码链接。

稳定笔记名 `<first-author-surname><year>-<短slug>.md`：
- surname 用首作者姓氏（小写、ASCII），year 取 4 位；
- 短 slug 取论文标题前 4~6 个词的词根小写，`-` 连接，只保留 `[a-z0-9-]`；
- 例如 `zhu2021-deformable-detr-transformers.md`。
- 若元数据缺失，回退为 PDF 文件名的规范化短名。

## Step 4：生成笔记

复制 `assets/paper-note-template.md` 为草稿，逐节填写并**删除所有 HTML 注释（填写说明）**。目标：一个没有论文在手也能被 AI 快速解答的完整知识库条目。各节要求与优先级如下（优先级高的先写全、写透）：

1. 核心结论：2~5 句讲清——这篇论文解决什么问题、提出什么方法、达到什么效果、对遥感视觉有何可借鉴点。
2. 背景与动机：问题定义、任务/数据、前人基线差在哪、本文切入角度。综述式罗列背景文献不是重点。
3. 方法机制（最花功夫）：按模块/阶段讲解；每个关键公式用 `$$...$$` 块给出并附三件事——符号说明、它“在做什么”的直观解释、在方法流程中的位置；复杂机制用中文伪代码或“输入→输出”描述；指出关键设计选择与备选方案被拒的原因（若有）。
4. 创新点分析：逐条列出。每条**必须**包含：相对哪个基线/前作的改变、解决的机制问题、论文中的实验证据（锚点）、代价/局限、以及“在我做遥感的方向是否仍成立”的推理。缺证据的条目标为 `主张待验证`，不得写成结论。
5. 实验与结果：数据集、任务设定、指标、对比基线、关键表格/图结论、消融揭示了什么、失败/表现差的场景。
6. 复现实用性审计：能否复现、值不值得复现。见 Step 5a。
7. 迁移到我的研究：给遥感视觉（如检测/分割/变化检测/多模态融合/少样本等）的具体切入假设，说明前提条件、需要的最小改动、最低成本验证实验与验收指标。只给可执行的条件式建议，不假装了解用户项目。
8. 局限与可写论文的选题：本文未解决的失败场景、与近期工作的重叠风险、可证伪假设、最低成本实验。
9. 下一步相关论文：见 Step 5b。
10. 引用与溯源：标准 Markdown 引用、本地 PDF 路径、生成日期、证据覆盖与 OCR 说明。

## Step 5a：复现审计（允许联网，只核验官方来源）

- 优先从 PDF 内声明的代码链接定位作者官方仓库（GitHub/GitLab/项目主页）；只核验作者关联的官方链接，不用网页搜索猜测非官方复现。
- 逐项核验并写入“复现实用性审计”：仓库当前是否存在、是否公开、是否含训练与推理代码、是否有权重/数据、License、最近活跃度、README 中的复现说明。官方仓库可访问才写结论；访问失败或 PDF 未提供链接一律写 `未核验`，注明日期。
- 若联网工具完全不可用，写明 `联网不可用`，把 PDF 内声明的链接原样记录为 `待核验`。

## Step 5b：关联论文推荐（允许联网，只输出元信息不下载）

- 用可用的学术检索（arXiv、Semantic Scholar、OpenAlex 等）找：同一问题不同路线、复用本文核心机制的后续工作、直接改进/指出本文缺陷的工作。只要值得读就可以推荐，但**排除纯背景/综述论文**（除非本文本身就是综述）。
- 每篇只输出：标题、年份、发表渠道、与本文的共同问题/共同机制、为什么值得下一篇读、检索来源与检索日期。
- 输出按发表时间**从新到旧**排序；条目数量不限但宁缺毋滥，去掉仅关键词重合的噪声。
- 检索失败时退化为：从本文参考文献 + 本地 `paper-notes/` 已有笔记中推荐，并注明局限。

## Step 6：写入笔记

```text
uv run --no-project python "<skill>/scripts/merge_note.py" "<草稿.md>" "<paper-notes>/<稳定名>.md"
```

- 首次运行创建文件；重跑时自动**整篇覆写自动内容**，但把旧文件 `<!-- USER-NOTES:START -->` 与 `<!-- USER-NOTES:END -->` 之间的用户批注原样保留。
- 模板中的用户批注区放在“我的批注”节，请提示用户可在此积累自己的疑问与扩展。

## Step 7：公式与成品校验

```text
uv run --no-project python "<skill>/scripts/check_math.py" "<paper-notes>/<稳定名>.md"
```

- 修掉所有报错（括号不配对、分隔符未闭合、MathJax 不支持的宏/环境等）。
- 最后请用户在 Obsidian 中打开笔记预览，确认所有 `$$...$$` 公式正常渲染；如渲染异常，按其反馈修正 LaTeX。

## Step 8：更新索引

```text
uv run --no-project python "<skill>/scripts/update_index.py" --dir <论文库根目录>/paper-notes
```

- 校验生成的 `index.md` 表格（论文、年份、渠道、作者、标签、链接），确认本论文已出现。

## 收尾汇报

向用户简报：生成了哪个笔记文件、核心结论一句话、哪些点标了 `待验证/未披露`（OCR 缺页、无开源、证据不足的创新点各几条）、推荐了哪几篇关联论文。把“请在 Obsidian 打开确认公式渲染”作为最后一步提示。
